# Activation Modes, Coexistence Boundaries, and Package Structure

Type: grilling
Status: resolved
Blocked by: 02

## Question

Once the core Occam-converged Trunk-to-Execution-Subagent protocol is locked in Ticket `02`, how should the skill/plugin be triggered (on-demand vs shared rule), how does it coexist cleanly with native Orchestrator sessions and isolated blind-review subagents (e.g., `egm-*`), what minimal `Execution Subagent` lifecycle/reset rule (if any) earns its place in V1, and what is the simplest repository layout ready for `/to-spec`?

## Answer

1. **Matt-Aligned Pure-Skill Plugin Packaging, Antigravity-First Scope & Unified Tier Lock ([ADR-0003](../../../docs/adr/0003-matt-pure-skill-packaging-and-shared-rule-adoption.md))**: Ship under the unified plugin and skill name `orchestrator` with zero top-level `rules/` directory, zero `hooks.json`, and zero persistent sidecars (`plugin.json`, `.claude-plugin/plugin.json`, `.claude-plugin/marketplace.json`, `README.md` with a concise `<=1 KB` copyable Antigravity shared-library/workspace rule snippet, self-contained `skills/orchestrator/` with a modular Harness Adapter Seam in `references/harnesses.md` reserving Claude Code / Codex stubs for future extension, and `tests/`). `SKILL.md` omits `disable-model-invocation: true` so shared `AGENTS.md` rules can load it on Antigravity, removes `"or names orchestrator"` from its frontmatter `description`, enforces Entry Gate #0 (requiring literal `/orchestrator` or explicit active `AGENTS.md` rule adoption), and applies one uniform tier rule: default and locked to `"flash"`, permitting `"pro"`, `"flash_lite"`, or `"inherit"` only when explicitly passed via `/orchestrator <tier>` across that request's `[plan review]` cycle before resetting to `"flash"` on the next new user message.
2. **Coexistence & Parallel Orthogonality with Isolated Subagents ([ADR-0004](../../../docs/adr/0004-coexistence-boundaries-and-foreman-subagent-delegation.md), [ADR-0005](../../../docs/adr/0005-universal-native-subagent-carrier-and-swarm-deference.md))**: Yield **unconditionally** when exact lowercase `exit_plan_mode` or `enter_plan_mode` tools exist (even on manual `/orchestrator`), and yield silently to explicit `/swarm` tasks and `[swarm]`/`[board]` `@<worker>` turns; verify **session origin (`step 0`)** in `SKILL.md`'s centralized Entry Gate via prompt framing on ordinary turns plus read-only `sync_memory.py check-origin` when resuming from compaction (`# Resuming from a compaction`), reinforced by `sync_memory.py sync` (`SKIP_SUBAGENT_SESSION` on `step 0` `SYSTEM_MESSAGE`) before dispatch, so `[Message] sender=<parent_uuid>` subagents, `[swarm]`/`[board]` `@<member>` sessions, compacted subagents, and `[EXECUTION SUBAGENT — SINGLE PHASE]` turns always run single-phase even when workspace `AGENTS.md` propagates into child sessions; keep `Execution Subagent` and `Isolated Subagents` completely parallel and orthogonal—attaching `Living Memory Window` and `flash` offloading solely to the bound `Execution Subagent` while leaving all plugin/skill `Isolated Subagents` (`egm-*`, `code-review`, `research`) 100% governed by their own skill/host model rules with zero special-case review routing inside `orchestrator`.
3. **Execution Subagent Lifecycle ([ADR-0002](../../../docs/adr/0002-checkpoint-bounded-living-memory-inheritance.md))**: Coupled directly to Trunk `CHECKPOINT` compaction epochs with sender-invariant intra-epoch `prefix_digest`, append-only `execution_subagent_ids` preserved across recovery resets, and symmetric two-phase `pending_sync` -> `bind` commit on both `SPAWN_NEW` and `RESUME_EXISTING`.
