# Activation Modes, Coexistence Boundaries, and Package Structure

Type: grilling
Status: resolved
Blocked by: 02

## Question

Once the core Occam-converged Trunk-to-Execution-Subagent protocol is locked in Ticket `02`, how should the skill/plugin be triggered (on-demand vs shared rule), how does it coexist cleanly with native Orchestrator sessions and isolated blind-review subagents (e.g., `egm-*`), what minimal `Execution Subagent` lifecycle/reset rule (if any) earns its place in V1, and what is the simplest repository layout ready for `/to-spec`?

## Answer

1. **Single-Manifest Pure-Skill Packaging, Unified Official Mode & Static Scope-Precedence Tiering ([ADR-0003](../../../docs/adr/0003-matt-pure-skill-packaging-and-shared-rule-adoption.md))**: Ship **only** root `plugin.json` under the unified plugin and skill name `orchestrator` (deferring `.claude-plugin/` and `.codex-plugin/` until non-Antigravity clients are targeted) with zero top-level `rules/` directory, zero `hooks.json`, and zero persistent sidecars (`plugin.json`, `README.md` with `< 1,000`-byte copyable shared-library/project adoption snippet and `Seam 2B` checklist, self-contained `skills/orchestrator/` separating harness-neutral `references/execution-protocol.md` from Antigravity `references/harnesses.md`, and `tests/`). `SKILL.md` omits `disable-model-invocation: true`, omits `"or names orchestrator"`, and authorizes (a) explicit Antigravity `AGENTS.md`/`GEMINI.md` adoption, (b) literal `/orchestrator` chat-bar invocations or continuations of an earlier `/orchestrator` turn (Approve-First approvals, mid-flight cancels), and (c) inbound `[Message]` wakeups when read-only `state.json` holds a non-null `bound_subagent_id`, running **one unified Official Orchestrator mode** and resolving tier via static scope precedence (**workspace-local `AGENTS.md`/`GEMINI.md` > direct global `~/.gemini/GEMINI.md` > `@[...]`-imported shared engineering rules > built-in default `"flash"`** across `flash`, `pro`, `flash_lite`, `inherit`, halting cleanly on invalid tier values).
2. **Coexistence, Three-Way Routing & Parallel Orthogonality with Isolated Subagents ([ADR-0004](../../../docs/adr/0004-coexistence-boundaries-and-foreman-subagent-delegation.md), [ADR-0005](../../../docs/adr/0005-universal-native-subagent-carrier-and-swarm-deference.md))**: Yield **unconditionally** when exact lowercase `exit_plan_mode` or `enter_plan_mode` tools exist (even on manual `/orchestrator`), and yield silently to explicit leading/command `/swarm` tasks (distinct from prose mentions) and `[swarm]`/`[board]` `@<worker>` turns; evaluate uncompacted `step 0` origin check and **Direct Answer Gate** fast-path first (zero CLI calls on pure Q&A / zero-edit reviews even post-compaction, excluding inbound `[Message]` wakeups from `bound_subagent_id`), and whenever an edit, side-effect, `[plan review]`, or recovery turn sees host `<CONTEXT_SUMMARY>` or `# Resuming from a compaction` outside `<USER_REQUEST>`, run read-only `sync_memory.py check-origin` first (failing closed on `"SUBAGENT"`, `"UNKNOWN"`, or non-zero exit), backed up by `sync`'s `SKIP_SUBAGENT_SESSION` before dispatch; route inbound `[Message]` replies three ways (`sender == bound_subagent_id` -> `[plan review]`; `sender != bound_subagent_id` in `execution_subagent_ids` -> orphaned `Execution Subagent`, ignore/kill; all others -> parallel `Isolated Subagents` left 100% untouched, treating absent `state.json` as null binding/empty allowlist); attach `Living Memory Window` and `orchestrator-tier:` solely to `Execution Subagent`.
3. **Execution Subagent Lifecycle ([ADR-0002](../../../docs/adr/0002-checkpoint-bounded-living-memory-inheritance.md))**: Coupled directly to Trunk `CHECKPOINT` compaction epochs with ascending pre-expansion `compute_digest`, folded companion expansion (`content` and `PLANNER_RESPONSE` `tool_calls`) before the Turn-1 rewind guard, append-only `execution_subagent_ids` plus `retired_subagent_max_step` late-orphan quarantine updated on both rotation `bind` and non-purge `reset` (and preserved across default recovery resets), `< 40,000`-byte / `<= 750`-line CRLF-normalized UTF-8 LF pages, and atomic `state.json` two-phase `pending_sync` -> `bind` commit on both `SPAWN_NEW` and `RESUME_EXISTING`.
