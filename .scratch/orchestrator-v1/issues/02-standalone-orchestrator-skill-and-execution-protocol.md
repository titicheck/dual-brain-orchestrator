# 02: Standalone On-Demand Orchestrator Skill and Two-Phase Execution Protocol

**What to build:** A self-contained `/orchestrator` skill module (with Codex interface metadata and non-spontaneous model-invocable configuration), defense-in-depth Entry Gate, single-phase `Execution Subagent` protocol reference, and cross-harness adapter reference (Antigravity, Claude Code, Codex) that aligns verbatim with Official Orchestrator everywhere outside cross-session `Living Memory Window` synchronization—delivering proportional read-only planning, locked-vs-manual tier governance, autonomous small-deviation handling, all five Official early hand-back triggers (including `Re-plan if:`), ~30-step checkpoints, Review-Do-Not-Execute `[plan review]` adjudication, and untouched parallel `Isolated Subagent` orthogonality.

**Blocked by:** 01: Living Memory Window Synchronization CLI

**Status:** ready-for-agent

- [ ] Configures non-spontaneous yet model-invocable skill metadata and Codex skill interface metadata: omits human-only invocation blocks (`disable-model-invocation: true` and `allow_implicit_invocation: false`) so shared or workspace agent rules can adopt the skill across harnesses, while stating explicitly in the skill frontmatter description to load `orchestrator` only on explicit `/orchestrator` invocation or active shared/workspace agent-rule adoption—forbidding spontaneous self-activation on ordinary prompts—plus encodes the defense-in-depth Entry Gate (`step 0` human `<USER_REQUEST>` vs `[Message] sender=...` / `[swarm]` / `[board]` / `[EXECUTION SUBAGENT — SINGLE PHASE]`, exact lowercase `exit_plan_mode`/`enter_plan_mode` deference unless `/orchestrator` was manually invoked, and active `/swarm` deference).
- [ ] Encodes verbatim Official Orchestrator `Trunk Session` Plan Mode rules: Prompt Precedence, Direct Answer Gate (questions, explanations, and zero-edit reviews stay in-session), Approve-First Exception, Depth Matching (immediate 1–2 sentence `<plan>` for settled follow-ups vs read-only investigation + full five-part `<plan>` with Non-Override Safety Clause and `Re-plan if:` for non-trivial work), and immediate turn yield after async dispatch without polling.
- [ ] Enforces execution-tier governance and error discipline exclusively on the bound `Execution Subagent`: locks strictly to the fast tier (`flash` on Antigravity, `sonnet` on Claude Code, allowlisted fast model + `medium` effort on Codex) under Rule-Driven Auto Mode, defaults to that fast tier while permitting scoped tier overrides (`pro`, `flash_lite`, `inherit`, or harness equivalents) on manual `/orchestrator`, rotates cleanly via `--tier` in `sync`, and inspects workspace status + subagent logs without silently switching models upon quota/API errors.
- [ ] Encodes verbatim Official Orchestrator `Execution Subagent` rules (`[EXECUTION SUBAGENT — SINGLE PHASE]` header): ordered execution of the latest `<plan>`, autonomous handling of minor mechanical deviations (slightly moved target, obvious import, 1 retry before "failed twice"), ~30-turn self-counted status checkpoints, all five Official early hand-back triggers verbatim (1. failed twice, 2. false plan assumption, 3. unchosen approach, 4. unnamed edits/work, 5. `Re-plan if:` match), and structured five-part `<report>` final reply.
- [ ] Encodes verbatim Official `[plan review]` rules and parallel `Isolated Subagent` orthogonality: Non-Override Safety Clause on `<report>`, strict Review-Do-Not-Execute discipline, three-way exit (continue remaining steps, revise with undo / do-instead / verify, or report verified completion/stop), mid-flight user-message subagent status check, on-demand native subagent trajectory log inspection, zero interference with parallel `Trunk Session` `Isolated Subagents`, and zero LLM-authored history-page fallbacks on non-Antigravity harnesses (relying on self-contained `<plan>` + native `resume` / `followup_task`).
