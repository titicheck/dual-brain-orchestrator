# 02: Standalone On-Demand Orchestrator Skill and Two-Phase Execution Protocol

**What to build:** A self-contained, opt-in `/orchestrator` skill module—complete with `Trunk Session` logical Plan Mode instructions, `Execution Subagent` single-phase execution protocol, and cross-harness native subagent mappings for Antigravity, Claude Code, and Codex—enabling end-to-end two-phase planning, `Living Memory Window` inheritance and continuation, ~30-step scheduled checkpoints, five early hand-back triggers, unified `<report>` `[plan review]` adjudication, and natural two-model `Isolated Subagent` coexistence.

**Blocked by:** 01: Living Memory Window Synchronization CLI

**Status:** ready-for-agent

- [ ] Defines `Trunk Session` Plan Mode behavior matching Official Orchestrator fidelity: proportional planning depth (immediate 1–2 sentence `<plan>` for settled follow-ups; direct in-session response without spawning an `Execution Subagent` for questions, explanations, and standalone reviews; stop-and-present when plan approval is requested), read-only investigation discipline, and self-contained `<plan>` authoring (ordered steps, target modules/symbols, exact changes, verification commands and expected outputs, pitfalls, non-override safety framing, and `Re-plan if:` conditions).
- [ ] Enforces the single model-offload boundary: selects an explicit fast, cost-efficient execution model tier exclusively when spawning the bound `Execution Subagent` (never silently switching models on quota exhaustion or availability errors), while preserving untouched native `inherit` defaults and zero `Living Memory Window` injection across all `Isolated Subagents`.
- [ ] Preserves non-nested main-model review quality and execution-phase foreman delegation: prohibits bundling heavyweight audits or blind reviews (`egm-*`, two-axis code reviews) inside an `Execution Subagent` `<plan>` so they always dispatch directly from the `Trunk Session` while the Main Model is active (either standalone in Plan Mode or upon `[plan review]` return after implementation), while permitting nested execution-phase slice workers under `Execution Subagent` on nested-capable hosts (naturally capping at the execution model) with Hand-back Trigger #5 fallback on single-depth harnesses.
- [ ] Defines the single-phase `Execution Subagent` protocol and unified inbound `[plan review]` gate: sequential `<plan>` execution without re-planning, ~30-step scheduled review checkpoints, immediate stop on all five early hand-back triggers (step fails twice, false plan assumption, unmade decision, unrequested out-of-plan work, external/single-depth block), structured five-part `<report>` return, on-demand native subagent log inspection, and unmodified three-way `[plan review]` adjudication (continue remaining steps, revise with undo / do-instead / verify, or deliver verified user sign-off).
- [ ] Documents concrete native subagent creation, continuation, opaque-log scratch fallback, and zero-cost idle retention mappings across Antigravity, Claude Code, and Codex, verified end-to-end through live standalone `/orchestrator` lifecycle and `Isolated Subagent` coexistence scenarios.
