**What to build:** Implement [ADR-0007](../../../docs/adr/0007-session-bound-command-ownership.md) across the orchestrator skill so no session yields while a command it started is still running, keeping the Official Orchestrator role split unchanged: `Trunk Session` keeps all judgment and runs only synchronously returning commands; `Execution Subagent` keeps execution and reports only after its commands reach a terminal state.

## Problem & Evidence

1. V1 copied Official Part 2.4 (`observational run_command builds, tests, or queries`) and Part 7 (`run observational commands if needed to check`) verbatim. In Official Orchestrator's single thread this is harmless, but across two sessions a backgrounded command binds host wakeups to `Trunk Session`.
2. In production session `L0-3` (`d1e362b3`), at `Trunk Session` steps `268`, `318`, `351`, and `378` (UTC `00:57:15`, `03:03:27`, `04:40:59`, `06:10:03`), each turn immediately followed the bound child's final step (`1276`, `1298`, `1339`, `1362` at matching timestamps) and began with `git show --stat <commit>`, meaning all four leaks happened inside Route 1 `[plan review]` turns where `Trunk Session` then launched offline benchmarks or memory probes itself. Antigravity auto-backgrounds commands beyond `10` seconds and delivers status wakeups (`~56–62 min`) to the owning session: `7` wakeups, each with `cache_read_tokens = 0`, burning `$9.83` plus `~90k` polling tokens (`~$11.18` total trunk waste).
3. Same-session control (`07:37–08:57`): an `80`-minute benchmark owned by `Execution Subagent` caused `0` intermediate `Trunk Session` wakeups and cost `$0.73`.
