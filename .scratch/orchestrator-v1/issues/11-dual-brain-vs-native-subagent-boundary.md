## Converged Conceptual Boundary (Two-Layer Orthogonal Model)

- **Layer 1 (Unified Dual-Brain Primary Agent):** `Trunk Session` (planning half) + single strongly-bound `Execution Subagent` (mounted execution half) form one logical primary agent isomorphic to native `Orchestrator`. `Execution Subagent` is logically part of the primary agent, **not** a domain/task subagent (`invoke_subagent` is solely its host transport carrier). Single 1:1 binding, `state.json` schema, and static `orchestrator-tier:` remain unchanged.
- **Positive Exclusive Scoping:** `orchestrator` mechanics (`orchestrator-tier:`, `Living Memory Window`, `<plan>`/`<report>`, `[plan review]`, and Route 2 orphan cleanup) apply **exclusively** to the single bound `Execution Subagent` (while Entry Gate 3 prevents `orchestrator` recursion in all spawned children). All other native subagents - both normal engineering subagents (`research` exploration, parallel `self` slice implementers, reviewers) and third-party plugin/skill `Isolated Subagents` (`egm-*`, `code-review`, `browser`, etc.) - operate outside `orchestrator` mechanics with zero `Living Memory Window` injection and remain untouched by `orchestrator-tier:`.
- **Native Tiering & Uncapped Depth:** Non-bound native subagents (including child subagents spawned inside `Execution Subagent`) follow native host behavior and active workspace/plugin/task tier rules (`subagent-default-tier:`, per-plugin overrides, or native default) with **no** hardcoded `Model="inherit"` override and **no** custom depth cap (handing back via Trigger #2 only if a host runtime limit blocks nested delegation).
- **Active-Brain Attribution & Child-Lifecycle Parity (Zero State-Machine Growth):**
  - Planning / read-only / review turns (`Trunk Session` active) -> spawn strictly read-only or review-only native subagents directly from `Trunk Session` (Route 3); workspace edits, state mutations, and external side effects dispatch strictly via `<plan>` to the bound `Execution Subagent` (zero direct-write Route 3 bypass).
  - Execution / mutation / parallel-slice turns (`Execution Subagent` active) -> `Execution Subagent` may delegate in-scope sub-tasks to native child subagents without violating ordered execution or Triggers #3/#4, awaits them reactively without polling or timers, consolidates/verifies results before returning one `<report>` to `Trunk Session` (never delivering `<report>` while a started child subagent is running, never allowing child subagents to report directly to `Trunk Session`, and terminating any still-running child subagent before early hand-back). Recovery in `harnesses.md` distinguishes `"idle"` parents in an active reactive wait on unreturned commands or child subagents from genuinely stalled turns, and runs cascading `kill` (covering nested descendants and `branch` workspaces) before `reset` on mid-flight cancel/redirect.
- **Release Packaging:** Bump `plugin.json` `"version"` to `"1.1.2"`.
