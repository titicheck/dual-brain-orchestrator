# Coexistence Boundaries, Two-Model Natural Inheritance, and Foreman Delegation

To coexist cleanly with native Orchestrator sessions, prevent recursive Plan/Execute loops when `rules/AGENTS.md` is inherited by child subagents, and preserve both fresh-context isolation and Official Orchestrator's two-active-model `Model: "inherit"` semantics across multi-agent skills (`egm-review`, `code-review`, `subagent-driven-development`), we enforce four boundaries: (1) when native `exit_plan_mode` or `enter_plan_mode` is already present in the toolset, `rules/AGENTS.md` yields silently to the host's native Orchestrator unless `/orchestrator` is explicitly invoked; (2) `rules/AGENTS.md` activates exclusively on top-level human conversations initiated by `<USER_REQUEST>`, remaining inert in any child subagent session woken by an inter-agent `<SYSTEM_MESSAGE>` (`[Message] timestamp=... sender=<parent_uuid> ...`) so subagents always run single-phase; (3) explicit execution-model selection applies solely when spawning the bound `Execution Subagent` (replacing `exit_plan_mode`'s host model hot-swap), while all other subagent calls retain untouched `Model: "inherit"` defaults and zero `Living Memory Window` injection; and (4) heavyweight audits and reviews (`egm-*`, `code-review`) are never bundled inside an `Execution Subagent` `<plan>`—they run directly from the `Trunk Session` while the Main Model is active (either immediately in Plan Mode for standalone reviews or at `[plan review]` after implementation returns `<report>`) so `Isolated Subagent` reviewers naturally inherit the Main Model, whereas execution-phase slice workers spawned nested under `Execution Subagent` (`depth = 1`) naturally inherit and cap at the execution model (with Hand-back Trigger #5 fallback to `Trunk Session` dispatch on single-depth harnesses).
