# Coexistence Boundaries and Execution Subagent Foreman Delegation

To coexist cleanly with native Orchestrator sessions, prevent recursive Plan/Execute loops when `rules/AGENTS.md` is inherited by child subagents, and preserve fresh-context isolation and quota efficiency for multi-agent skills (`egm-review`, `code-review`, `subagent-driven-development`), we enforce three boundaries: (1) when native `exit_plan_mode` or `enter_plan_mode` is already present in the toolset, `rules/AGENTS.md` yields silently to the host's native Orchestrator unless `/orchestrator` is explicitly invoked; (2) `rules/AGENTS.md` activates exclusively on top-level human conversations initiated by `<USER_REQUEST>`, remaining inert in any child subagent session woken by an inter-agent `<SYSTEM_MESSAGE>` (`[Message] timestamp=... sender=<parent_uuid> ...`) so subagents always run single-phase; and (3) `Living Memory Window` synchronization attaches strictly to the single bound `Execution Subagent` replacing `exit_plan_mode`, leaving all other `invoke_subagent` calls (`research`, `egm-*`, slice implementers, code reviewers) as unmodified zero-history calls, while allowing the `Execution Subagent` (`depth = 1`) to act as execution foreman on nested-capable hosts (naturally passing its offloaded execution model to `Model: "inherit"` child workers just as Official Orchestrator's Execution Mode does) and handing back via Trigger #5 for `Trunk Session` (`depth = 0`) dispatch on single-depth harnesses.
