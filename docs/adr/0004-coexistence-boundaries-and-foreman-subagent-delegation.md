# Coexistence Boundaries, Three-Way Inbound Routing, and Isolated Subagent Orthogonality

## Context

In Antigravity workspaces, `AGENTS.md` / `GEMINI.md` rules propagate automatically into child subagents, native `Orchestrator` virtual-model sessions expose same-thread hot-swap tools, `/swarm` workflows coordinate multi-agent boards, and native subagents—both standard engineering subagents (`research`, parallel `self` slice workers, reviewers) and third-party plugin/skill `Isolated Subagents` (`egm-*`, `code-review`)—coexist alongside the dual-brain primary agent. Without strict entry ordering, sender-scoped `[Message]` routing, and a clear logical-vs-physical boundary between the bound `Execution Subagent` and ordinary native subagents, `orchestrator` risks recursing inside child subagents, starving ordinary native subagent delegation during large plans, or colliding with non-bound subagent wakeups.

## Decision

1. **Ordered Entry Gate With Zero-CLI Pure Q&A Fast-Path**:
   - **Gate 0 (Activation Authority)**: Authorize when active `AGENTS.md` / `GEMINI.md` rules adopt `orchestrator`, literal `/orchestrator` was invoked in the current or earlier turn of the session, or read-only inspection of `<Artifact Directory Path>/scratch/orchestrator/state.json` (when present) shows non-null `bound_subagent_id`.
   - **Gate 1 (Unconditional Native Orchestrator Deference)**: If exact lowercase `exit_plan_mode` or `enter_plan_mode` exists in the toolset, yield unconditionally (even if `/orchestrator` was typed).
   - **Gate 2 (Active `/swarm` Deference)**: Yield silently to explicit leading/command `/swarm` invocations (distinct from prose mentioning `/swarm`) and `[swarm]` / `[board]` `@<worker>` turns.
   - **Gate 3 (Uncompacted Root Check + Direct Answer Fast-Path + Fail-Closed Compaction Check)**: On uncompacted conversations, yield single-phase if `step 0` started with `[Message] timestamp=... sender=<parent_uuid>` (no preceding user turns), `[swarm]`, `[board]`, or `[EXECUTION SUBAGENT — SINGLE PHASE]`. Otherwise, evaluate the **Direct Answer Gate** first: when the turn is a pure question, explanation, or zero-edit review and is **not** an inbound `[Message]` wakeup from `state.bound_subagent_id` or a Route 2 orphaned `state.execution_subagent_ids` member, answer directly in-session and stop with **zero** `sync_memory.py` calls or disk writes (synchronous read-only observational commands remain permitted per ADR-0007)—even post-compaction. Only on turns proceeding toward workspace edits, external side effects, `[plan review]`, or recovery: if host `<CONTEXT_SUMMARY>` or `# Resuming from a compaction` framing appears outside user text, run read-only `skills/orchestrator/scripts/sync_memory.py check-origin` first and yield single-phase on `"SUBAGENT"`, `"UNKNOWN"`, or any non-zero exit code—backed up by `sync`'s `SKIP_SUBAGENT_SESSION` guard before any dispatch. Verify `invoke_subagent` and `send_message` only after reaching dispatch.

2. **Three-Way Inbound `[Message]` Routing**:
   - If `state.json` is absent, treat `bound_subagent_id` as `null` and `execution_subagent_ids` as `[]` with zero CLI writes.
   - **`sender == state.bound_subagent_id`**: Enter Official `[plan review]` (never letting `[plan review]` edits happen directly in `Trunk Session`; if the user sends an additive request while `manage_subagents("list")` shows `"running"` or `"waiting_for_dependents"`, either yield to await active execution completion or `kill` + `reset` + re-plan cleanly without double-messaging an active or reactively waiting child).
   - **`sender != state.bound_subagent_id` and `sender in state.execution_subagent_ids`** (including superseded/killed branches): Orphaned `Execution Subagent`—ignore its payload and `kill` if still running without entering `[plan review]`; `retired_subagent_max_step` keeps its late `<report>` out of subsequent `Living Memory Window` pages.
   - **`sender not in state.execution_subagent_ids`**: Non-bound native subagent (`research`, `egm-*`, `code-review`, or other `Isolated Subagent`) or host system notice—process normally in `Trunk Session` with zero `state.json` mutation or `[plan review]` gating.
   - When on-demand raw inspection is needed after compaction, `references/harnesses.md` derives `<bound_subagent_id>`'s `logAbsoluteUri` deterministically as the sibling transcript `<parent of Artifact Directory Path>/<bound_subagent_id>/.system_generated/logs/transcript.jsonl`.

3. **Unified Dual-Brain Scope, Orthogonal Native Subagent Layer, and Active-Brain Attribution**:
   - **Logical-vs-Physical Decoupling**: `Trunk Session` (planning half) and its single strongly-bound `Execution Subagent` (mounted execution half) logically form one unified primary agent isomorphic to native `Orchestrator`; native `invoke_subagent` is solely the host transport carrier for `Execution Subagent`, not its domain identity as a task subagent.
   - **Positive Exclusive Scoping**: `orchestrator` mechanics (`orchestrator-tier:`, `Living Memory Window`, `<plan>`/`<report>`, `[plan review]`, and Route 2 orphan cleanup) apply **exclusively** to the single bound `Execution Subagent` (while Entry Gate 3 prevents `orchestrator` recursion in every spawned child). All other native subagents—both ordinary engineering subagents and plugin/skill `Isolated Subagents`—operate outside `orchestrator` mechanics with zero injected `Living Memory Window` and remain untouched by `orchestrator-tier:`.
   - **Active-Brain Attribution & In-Plan Delegation**: Parent attribution follows whichever half is currently active: during planning, read-only investigation, or review turns (`Trunk Session` active), strictly read-only or review-only native subagents spawn from `Trunk Session` (entering Route 3; any workspace edits, state mutations, or external side effects dispatch strictly via `<plan>` to `Execution Subagent`); during execution turns (`Execution Subagent` active), `Execution Subagent` may delegate in-scope sub-tasks (e.g., independent plan slices, lookups, or reviews) to native child subagents without violating ordered execution or Triggers #3/#4.
   - **Native Tiering & Uncapped Depth**: Removed the legacy hardcoded assumption that nested workers must inherit the active execution model tier; child subagents spawned by `Execution Subagent` follow native host behavior and active workspace/plugin/task tier rules (such as `subagent-default-tier:`). No custom depth cap is imposed; if host runtime limits block nested delegation, `Execution Subagent` executes the slice directly when delegation was optional or hands back via Trigger #2 when `<plan>` required delegation. Live Antigravity `depth=1 -> depth=2` probe (`286db00e` spawned from bound `depth=1` `b6415f63`, `nesting_depth=2`, `step 0` Gate 3(a) non-recursion) confirmed end-to-end host support.
   - **Child-Subagent Lifecycle & Recovery Symmetry**: Child subagents report exclusively back to `Execution Subagent` (never directly to `Trunk Session`) and never receive bound-executor handoff framing or `Living Memory Window` pages. `Execution Subagent` awaits started child subagents reactively without polling or timers, consolidates/verifies outputs before one `<report>`, and terminates any still-running child subagents before early hand-back. Live Antigravity probes (`1baa9297` background `run_command`, `6b9d9b6d` child/timer, and `ef421003`/`4120dffe` `depth=2` cascade `kill`) confirmed that `manage_subagents(Action="list")` natively reports `"waiting_for_dependents"` for all unreturned async dependencies (background commands, timers, and child subagents) and `manage_subagents(Action="kill")` cascades to nested descendants and armed background tasks; `harnesses.md` therefore checks quota/API errors first before any stall recovery or `--force-spawn` respawn on `"idle"`/`"stopped"`, treats `"waiting_for_dependents"` identically to `"running"`, and runs `kill` before `reset` on mid-flight cancel/redirect.

## Consequences

- Pure Q&A turns execute with zero CLI overhead both before and after compaction, while edits, tagless/tagged `[Message]` wakeups from `bound_subagent_id`, and `[plan review]` continuations retain strict fail-closed subagent non-recursion.
- Ordinary native engineering subagents and `Isolated Subagents` (`research`, `egm-*`, `code-review`, parallel `self` slice workers) coexist orthogonally alongside the unified dual-brain primary agent with clean active-brain attribution, native tiering, and symmetric child-lifecycle recovery.
