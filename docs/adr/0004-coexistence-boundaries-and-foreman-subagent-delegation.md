# Coexistence Boundaries and Parallel Orthogonality with Isolated Subagents

To coexist cleanly with native Orchestrator sessions, prevent recursive Plan/Execute loops inside child subagents, and avoid Official Orchestrator's same-thread temporal coupling between execution offloading and plugin/skill subagents, we enforce three orthogonal boundaries: (1) when native `exit_plan_mode` or `enter_plan_mode` is already present in the toolset (or when `/swarm` is invoked for the active task), Rule-Driven Auto Mode (adopted via shared-library or workspace `AGENTS.md` / `CLAUDE.md` and enforced as a defense-in-depth entry gate inside `SKILL.md`) yields silently unless `/orchestrator` is explicitly invoked; (2) Rule-Driven Auto Mode checks **session origin (`step 0`)**—activating exclusively on top-level human conversations initiated by `<USER_REQUEST>` (including mid-session `<report>` return wakeups on that `Trunk Session`), while remaining strictly inert when `step 0` is an inter-agent `<SYSTEM_MESSAGE>` (`[Message] timestamp=... sender=<parent_uuid> ...`) or `[swarm]`/`[board]` `@<member>` assignment, or when the prompt carries `[EXECUTION SUBAGENT — SINGLE PHASE]`, guaranteeing child subagents running inside workspaces that inherit `AGENTS.md` always execute single-phase; and (3) `Execution Subagent` and `Isolated Subagents` operate as parallel, independent channels from the `Trunk Session`—`Living Memory Window` synchronization and fixed fast-tier offloading apply solely to the single bound `Execution Subagent`, whereas all `Isolated Subagents` invoked by plugins or skills (`egm-*`, `code-review`, `research`, etc.) receive zero `Living Memory Window` injection and retain 100% of their own native skill/client model rules and explicit user parameters without special-case routing inside `orchestrator` (with only nested workers spawned from inside an active `Execution Subagent` naturally inheriting and capping at the execution model, or handing back via Trigger #2 on single-depth harnesses).
