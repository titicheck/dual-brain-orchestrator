# Coexistence Boundaries and Parallel Orthogonality with Isolated Subagents

To coexist cleanly with native Orchestrator sessions, prevent recursive Plan/Execute loops inside child subagents, and avoid Official Orchestrator's same-thread temporal coupling between execution offloading and plugin/skill subagents, we enforce three orthogonal boundaries: (1) when native `exit_plan_mode` or `enter_plan_mode` is already present in the toolset (or when `/swarm` is invoked), `rules/AGENTS.md` yields silently unless `/orchestrator` is explicitly invoked; (2) `rules/AGENTS.md` activates exclusively on top-level human conversations initiated by `<USER_REQUEST>`, remaining inert in any session woken by an inter-agent `<SYSTEM_MESSAGE>` (`[Message] timestamp=... sender=<parent_uuid> ...`) or `[swarm]`/`[board]` `@<member>` assignment so child subagents always run single-phase; and (3) `Execution Subagent` and `Isolated Subagents` operate as parallel, independent channels from the `Trunk Session`—`Living Memory Window` synchronization and fixed `flash` offloading apply solely to the single bound `Execution Subagent`, whereas all `Isolated Subagents` invoked by plugins or skills (`egm-*`, `code-review`, `research`, etc.) receive zero `Living Memory Window` injection and retain 100% of their own native skill/client model rules and explicit user parameters without special-case routing inside `orchestrator` (with only nested workers spawned from inside an active `Execution Subagent` naturally inheriting and capping at the execution model, or handing back via Trigger #5 on single-depth harnesses).
