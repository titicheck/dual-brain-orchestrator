# Single-Manifest Pure-Skill Packaging, Unified Official Mode, and Static Scope-Precedence Tiering

To keep V1 minimal, align directly with Official Orchestrator, and avoid duplicating configuration across everyday projects, we ship **only** root `plugin.json` (`{"name": "orchestrator", "version": "1.0.0", "description": "...", "skills": ["./skills/orchestrator"]}`) alongside `README.md` (hosting install guidance, the `< 1,000`-byte copyable shared-engineering-library / project `AGENTS.md` adoption snippet, and the 4-point `Seam 2B` Antigravity live smoke verification checklist), `skills/orchestrator/{SKILL.md, scripts/sync_memory.py, references/{execution-protocol.md, harnesses.md}}` (keeping core two-phase protocol rules cleanly separated from Antigravity runtime bindings in `references/harnesses.md` for future extension), and Python `unittest` suites `tests/{test_sync_memory.py, test_package_contracts.py, fixtures/}`—with **zero** `.claude-plugin/` or `.codex-plugin/` directories in V1 (deferred until non-Antigravity clients are targeted), zero top-level `rules/`, zero `hooks.json`, and zero persistent sidecars. Following the unified ergonomics of `karpathy-guidelines` and `superpowers`, we eliminate any separate "Manual Mode" or conversational `/orchestrator <tier>` argument-parsing state machine: `orchestrator` runs **one unified Official Orchestrator workflow** whether adopted continuously via `AGENTS.md` or invoked directly from the Antigravity chat bar (`/orchestrator`), gated by `SKILL.md` frontmatter (omitting `disable-model-invocation: true` and `"or names orchestrator"`) and Entry Gate #0—authorizing when (a) an active Antigravity shared or project `AGENTS.md` rule adopts `orchestrator`, (b) the user invoked literal `/orchestrator` in the current turn or an earlier turn of the current session (preserving Approve-First approvals, Trigger #3 replies, and mid-flight cancels), or (c) `state.json` has a non-null `bound_subagent_id` (covering `<SYSTEM_MESSAGE>` `[Message] timestamp=... sender=<id>` wakeups entering logical `[plan review]`, which carry **no** literal `[plan review]` host prefix). Tool verification (`invoke_subagent` and `send_message`) runs **only after Gates 0–3 pass**, halting cleanly with an unsupported-client notice on incompatible runtimes while letting `/swarm` workers yield silently via Gate 2. Execution tier is governed **solely by canonical static rule declarations** (`orchestrator-tier: <flash|pro|flash_lite|inherit>`, conversational prompts never alter tier), resolving by natural scope precedence: **project-level `AGENTS.md` `orchestrator-tier:` > shared-engineering-library `AGENTS.md` `orchestrator-tier:` > built-in default `"flash"`**, and always passed explicitly via `sync_memory.py sync --tier <resolved_tier>` on every sync call. Everyday projects inheriting the shared engineering library require zero `orchestrator` configuration in their own `AGENTS.md`, adding a project `orchestrator-tier:` override only when an individual project wants a different execution tier.
