# Single-Manifest Pure-Skill Packaging, Unified Official Mode, and Static Scope-Precedence Tiering

To keep V1 minimal, align directly with Official Orchestrator, and avoid duplicating configuration across everyday projects, we ship **only** root `plugin.json` (`{"name": "orchestrator", "version": "1.0.0", "description": "...", "skills": ["./skills/orchestrator"]}`) alongside `README.md` (hosting install guidance, the `< 1,000`-byte copyable shared-engineering-library / project `AGENTS.md` adoption snippet, and the 4-point `Seam 2B` Antigravity live smoke verification checklist), `skills/orchestrator/{SKILL.md, scripts/sync_memory.py, references/{execution-protocol.md, harnesses.md}}` (keeping core two-phase protocol rules cleanly separated from Antigravity runtime bindings in `references/harnesses.md` for future extension, and halting cleanly with an unsupported-client notice if invoked where `invoke_subagent`/`send_message` are absent), and Python `unittest` suites `tests/{test_sync_memory.py, test_package_contracts.py, fixtures/}`—with **zero** `.claude-plugin/` or `.codex-plugin/` directories in V1 (deferred until non-Antigravity clients are targeted), zero top-level `rules/`, zero `hooks.json`, and zero persistent sidecars. Following the unified ergonomics of `karpathy-guidelines` and `superpowers`, we eliminate any separate "Manual Mode" or conversational `/orchestrator <tier>` argument-parsing state machine: `orchestrator` runs **one unified Official Orchestrator workflow** whether adopted continuously via `AGENTS.md` or invoked directly from the Antigravity chat bar (`/orchestrator`), gated by `SKILL.md` frontmatter (omitting `disable-model-invocation: true` and `"or names orchestrator"`) and Entry Gate #0 (authorizing literal `/orchestrator` chat invocation, active Antigravity `AGENTS.md` adoption, or an inbound `<SYSTEM_MESSAGE>` `[plan review]` wakeup from `state.json`'s `bound_subagent_id`). Execution tier is governed **solely by static rule declarations** (conversational prompts never alter the tier), resolving by natural scope precedence: **project-level `AGENTS.md` explicit tier > shared-engineering-library `AGENTS.md` tier > built-in default `"flash"`** (`{"flash", "pro", "flash_lite", "inherit"}`, passed to `sync_memory.py --tier`). Everyday projects inheriting the shared engineering library require zero `orchestrator` configuration in their own `AGENTS.md`, adding a project `AGENTS.md` override only when an individual project wants a different execution tier.
