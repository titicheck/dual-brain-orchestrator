# Single-Manifest Pure-Skill Packaging, Unified Official Mode, and Static Scope-Precedence Tiering

## Context

In Antigravity (`agy-customizations/docs/plugins.md`), enabling or disabling a plugin is atomic across the entire bundle, and any top-level `rules/` folder bundled inside an enabled plugin automatically injects into every session. Meanwhile, V1 targets Antigravity single-model sessions exclusively while reserving a clean seam for future Claude Code or Codex adapters. Maintaining separate "manual" vs "global" modes or conversational `/orchestrator <tier>` overrides adds fragile state parsing and execution-tier drift.

## Decision

- **Single-Manifest Pure-Skill Layout**: Ship **only** root `plugin.json` (`{"name": "orchestrator", "version": "<semver>", "description": "...", "repository": "..."}`) alongside `README.md`, `README.zh-CN.md`, `skills/orchestrator/{SKILL.md, scripts/sync_memory.py, references/{execution-protocol.md, harnesses.md}}` (keeping core two-phase protocol rules in `references/execution-protocol.md` separated from Antigravity runtime bindings in `references/harnesses.md` for future extension), and `tests/{test_sync_memory.py, test_package_contracts.py}`—with **zero** `.claude-plugin/` or `.codex-plugin/` directories in V1, zero bundled `rules/`, zero `hooks.json`, and zero persistent sidecars.
- **Model-Invocable Frontmatter With Active-Session Continuity**: `SKILL.md` frontmatter omits `disable-model-invocation: true` so shared or workspace `AGENTS.md` / `GEMINI.md` rules can adopt `orchestrator`, and omits `"or names orchestrator"` so ordinary discussions mentioning the word are never hijacked. Its description activates `orchestrator` across three distinct triggers: (1) explicit Antigravity `AGENTS.md` / `GEMINI.md` rule adoption, (2) literal `/orchestrator` chat-bar invocation or continuation of an earlier `/orchestrator` turn in the same conversation (including Approve-First approvals, follow-up turns, or mid-flight redirects/cancels), or (3) inbound `<SYSTEM_MESSAGE>` `[Message]` wakeups when `<Artifact Directory Path>/scratch/orchestrator/state.json` exists with a non-null `bound_subagent_id` (inspected read-only via `read_file`).
- **One Unified Official Mode & Static Scope-Precedence Tiering**: Whether adopted via shared rules (`README.md` / `README.zh-CN.md`'s `< 1,000`-byte copyable snippets) or invoked via `/orchestrator`, `orchestrator` executes the exact same Official Orchestrator workflow. Following a single-source-of-truth (SSOT) thin-pointer boundary, the copyable adoption snippet carries only a whitelist-first pre-load activation gate pointing to `SKILL.md` (top-level human-originated or post-compaction single-model sessions without exact lowercase `exit_plan_mode`/`enter_plan_mode` and outside `/swarm`, when planning or executing tasks that modify files, state, or external side effects, or when resuming the bound `Execution Subagent`) and the static `orchestrator-tier:` lock—leaving internal Three-Way Routing, post-compaction `check-origin`, and host tool checks exclusively in `SKILL.md` so downstream `AGENTS.md` files do not churn when internal orchestration rules evolve. Execution tier uses one canonical directive—`orchestrator-tier: <flash|pro|flash_lite|inherit>`—resolved solely from static rules in strict specificity order: **workspace-local `AGENTS.md` / `GEMINI.md` > direct global `~/.gemini/GEMINI.md` > `@[...]`-imported shared engineering rules (e.g., `engineering-kit/rules/AGENTS.md`) > built-in default `"flash"`** (within a single rendered rule block—such as inline `@[...]` expansion—the last `orchestrator-tier:` declaration wins). Conversational mentions never change the tier; invalid `orchestrator-tier:` directives halt dispatch and report the rule error to the user; workspace `orchestrator-tier:` edits trigger clean rotation via `tier != bound_tier`.

## Consequences

- Everyday projects importing a shared engineering library require zero `orchestrator` configuration in their own `AGENTS.md`, while direct global or project overrides resolve predictably without ambiguity.
- Unconfigured `/orchestrator` conversations continue seamlessly across Approve-First approvals, mid-flight interrupts, compaction, and `[Message]` `[plan review]` wakeups without falsely triggering on unrelated conversations.
- Tool availability verification (`invoke_subagent` and `send_message`) executes **only after** Gates 0–3 pass (and after the Direct Answer Q&A fast-path), halting cleanly on unsupported clients without blocking read-only Q&A or `/swarm` turns.
