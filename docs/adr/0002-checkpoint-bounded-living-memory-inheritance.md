# Checkpoint-Bounded Living Memory Inheritance (`v2.0.0` Stateless `Always-New` Snapshots)

## Context

An Antigravity `Execution Subagent` runs in its own native subagent conversation rather than sharing the parent thread. Without transferring the `Trunk Session`'s active context, the subagent loses conversational decisions and user constraints; conversely, dumping full raw transcripts including tool outputs bloats context (`211-818 KB` median/peak in `L0-1` vs Antigravity `read_file`'s `46,080`-byte / `800`-line read cap), and lossy LLM summaries violate lossless intent preservation.

Empirical `L0-1` through `L0-4` trajectory measurements (`44.1 KB` initial `Living Memory Window` median, `75/75` self-contained `<plan>` dispatches, `0/15` memory-loss failures on fresh spawns, `4.27s` empirical spawn boot, and `sim-vs-sim` backtests showing stateless `Always-New` outperforming both `v1.1.x` `RESUME_EXISTING` and `v1.2.x` `Pure q=0` cost-rotation at `+$13.45` `1x` / `+$36.37` `2x`) established that an `Execution Subagent`'s memory after returning `<report>` carries zero semantic value—`RESUME_EXISTING` incremental deltas, `prefix_digest` continuity checks, and `v1.2.0` `Pure q=0` child-bloat heuristics were therefore superseded in `v2.0.0` by a stateless one-shot `SPAWN_NEW` snapshot (`N_max = 1`), completely eliminating cross-dispatch `10 KB / N` compaction truncation.

## Decision

A zero-dependency Python 3 standard-library CLI (`skills/orchestrator/scripts/sync_memory.py`, invoked via `py -3` on Windows or `python3` on POSIX relative to the loaded `SKILL.md` directory) resolves paths directly from `<Artifact Directory Path>` (`<appDataDir>/brain/<ConversationID>`)—reading `--transcript <Artifact Directory Path>/.system_generated/logs/transcript.jsonl` (and sibling `transcript_full.jsonl`) and persisting minimal 4-key session state under `--state-dir <Artifact Directory Path>/scratch/orchestrator`.

### Subcommands, Validation Order & Atomic Persistence
- **Exit codes & strict pre-mutation validation**: Overrides `ArgumentParser.error` so CLI argument/syntax errors exit `1` (`0` = success; `1` = invalid arguments, empty/whitespace `--subagent-id`, corrupt/non-dict/schema-invalid `state.json`, or `bind` with `pending_sync: null`; `2` = `OSError` reading `state.json` or logs, `OSError` in `main`, missing `--transcript` logs directory on uninitialized non-standard paths during `sync`, mid-file invalid UTF-8, mid-file corrupt/non-dict JSONL or missing/non-string `"type"` or non-list `"truncated_fields"` in primary or companion logs, or missing/bool/non-int/`< 0` `step_index`). `fold_jsonl_file` reads raw bytes and decodes strictly as UTF-8 first (preserving valid trailing JSON lines without `\n`), dropping an incomplete trailing UTF-8 sequence only when `UnicodeDecodeError` occurs on a file not ending in `b"\n"`, and ignoring only a final non-empty EOF line failing `json.loads`. Both `state.json` schema validation and `transcript.jsonl` folding + `SKIP_SUBAGENT_SESSION` enforcement execute **before** creating `--state-dir`, clearing `pages/page_*.md`, or writing `state.json`. All `state.json` writes use an atomic temp file + `os.replace` (with 3-attempt `15ms` `PermissionError` retry) inside `--state-dir`, and all `state.json` and `pages/page_*.md` writes use UTF-8 with `newline="\n"` (`\r\n` and bare `\r` normalized to `\n` across all extracted block inputs).
- **`check-origin --transcript <path>`**: Read-only check mutating zero files on disk, emitting `{"origin": "TRUNK" | "SUBAGENT" | "UNKNOWN"}` (returns `{"origin": "UNKNOWN"}` with exit `0` whenever `--transcript` does not exist even if its parent directory is absent or `folded` is empty; exits `2` on unreadable or corrupt existing logs). `classify_origin(folded)` first scans retained `SYSTEM_MESSAGE` records via outermost envelope parsing for unspoofable swarm/fork markers (`"You are @"` + `"Everything before this turn is @"` on headerless outer `<SYSTEM_MESSAGE>`, or `[Message] ... content=` starting with `"You have just started. Your assignment (recorded on the board as #"`) -> `"SUBAGENT"`, then checks `folded[min(folded)]` (supporting UI-branched human chats starting at `step_index > 0`): requires `type == "USER_INPUT"` and `source in (None, "USER_EXPLICIT")`, strips leading `<USER_REQUEST>` + whitespace when `"content"` is in `truncated_fields`, rejects `[swarm]`/`[board]`/`[EXECUTION SUBAGENT — SINGLE PHASE]` prefixes -> `"SUBAGENT"`, and otherwise returns `"TRUNK"`.
- **`sync --transcript <path> --state-dir <dir>`**:
  - **Turn-1 Empty-Transcript Grace**: When `--transcript` does not yet exist (provided `transcript_path.resolve().parent` exists **or** `transcript_path.resolve().parts[-3:] == (".system_generated", "logs", "transcript.jsonl")` under an existing `<Artifact Directory Path>`), is `0` bytes, or yields zero folded records after ignoring an incomplete trailing EOF line (and existing `state.json`, if present, is valid JSON matching the schema), preserves existing `execution_subagent_ids`/`retired_subagent_max_step`, clears stale `pages/page_*.md`, stages `pending_sync = {"synced_through": -1}`, and emits `SPAWN_NEW` (`{"action": "SPAWN_NEW", "checkpoint_step": -1, "synced_through": -1, "pages": []}`).
  - **Canonical Folding, Fail-Closed Origin Backstop, & Stateless Snapshot Export**: Folds records by `step_index` (later record at `k` invalidates earlier records at `>= k`) and enforces `classify_origin(folded) != "TRUNK"` `SKIP_SUBAGENT_SESSION` (`{"action": "SKIP_SUBAGENT_SESSION", "checkpoint_step": -1, "synced_through": -1, "pages": []}`, exit `0`, zero disk writes). For every `TRUNK` dispatch, exports the single full active-epoch `Living Memory Window` snapshot `[window_start .. max_folded_step]` (`window_start = max(0, latest_checkpoint_step)`), clears stale pages, stages `pending_sync = {"synced_through": max_folded_step}`, and emits `SPAWN_NEW` (`N_max = 1`).
  - **Zero-Copy Folded Companion Expansion**: Checks `_needs_companion_expansion` across `[window_start .. max_folded_step]` solely for `_EXTRACTABLE_TYPES` `"content"` truncation; when no extractable record is truncated (or `transcript_full.jsonl` is absent), returns `folded` without copying. Otherwise loads and **folds sibling `transcript_full.jsonl` by `step_index` (`later k invalidates >= k`)**, resolving solely via `comp_folded.get(step_idx)` with `type` and `_created_at_compatible` enforced unconditionally and copying only mutated entries.

### Lossless Window Extraction, Retired-Subagent Quarantine & Dual-Cap Pagination
- **`USER_INPUT` Boundary-Only Parser**: Normalizes `\r\n` and bare `\r` to `\n`. Consumes outer metadata strictly from standalone tag lines (`line.strip(" \t") == open_tag` / `close_tag`) with balanced tag-depth scanning (`depth = 1`) from string boundaries (never scanning interior user prose or inline `@[...]` file literals): strips leading/trailing `<USER_SETTINGS_CHANGE>...</USER_SETTINGS_CHANGE>` envelopes; strips `<ADDITIONAL_METADATA>...</ADDITIONAL_METADATA>` outer tags from leading/trailing metadata blocks while removing lines whose `.strip()` starts with `The current local time is:` and preserving remaining non-whitespace lines (resolved `@[ITEM]` mentions, uploaded attachment paths); only when the remaining trimmed core begins with `<USER_REQUEST>` and ends with `</USER_REQUEST>`, unwraps those outermost `<USER_REQUEST>` tags; joins `.strip()`-non-empty core and preserved metadata with `"\n\n"`; and skips empty/whitespace results.
- **`SYSTEM_MESSAGE` / `EPHEMERAL_MESSAGE` One-Pass Outer-Envelope Parser**: Normalizes `\r\n` to `\n` and inspects `s = content.lstrip(" \t\n")`. Accepts **exclusively** the single outer header candidate—`s` itself if `s.startswith("[Message] ")`, the line immediately after opening `<SYSTEM_MESSAGE>\n` if `s.startswith("<SYSTEM_MESSAGE>\n")`, or (only when `s` starts with neither) the single line immediately following the first standalone `\n<SYSTEM_MESSAGE>\n` line **provided** `s` starts with Antigravity's prose preamble (`s.startswith("The following is a <SYSTEM_MESSAGE>")`) followed solely by that single preamble line plus optional blank lines before that `<SYSTEM_MESSAGE>` tag line (blocking unwrapped task/error preambles and spoofed inner `[Message]` lines). Accepts records only when `<id> in state.execution_subagent_ids` **and** (`<id> == state.bound_subagent_id` or `step_index <= state.retired_subagent_max_step.get(<id>, step_index)`). Trims trailing `</SYSTEM_MESSAGE>` via `.rstrip()`, at most one `.removesuffix("</SYSTEM_MESSAGE>")`, and `.strip()`; extracts outermost `<report>...</report>` **retaining `<report>` tags** when `close_idx > open_idx`, or falls back to `.strip()`-non-empty `content=` text.
- **Other Records & Dual Page Cap**: Extracts CRLF-normalized, non-empty `CHECKPOINT` (`content.strip()`) and `PLANNER_RESPONSE` (`content.strip()`), ignoring `thinking`, `tool_calls`, `GENERIC`, and `ERROR_MESSAGE`. Clears stale `pages/page_*.md` only after validation and `SKIP_SUBAGENT_SESSION` pass. Renders `pages/page_001.md`, ... (absolute `.resolve()` paths) using `# Living Memory Window — Page 001\n\n`, per-block `## [Step <N>] <Role Label>\n<body>` (`(cont.)` on split blocks), and `"\n\n---\n\n"` separators, guaranteeing **both** `len(rendered_utf8) < 40000` and `line_count <= 750` (staying safely under Antigravity `read_file`'s `800`-line and `46,080`-byte limit).
- **`bind` & `reset` Lifecycle (4-Key Schema + Legacy Read Compat)**: `state.json` persists strictly 4 keys: `{ bound_subagent_id, execution_subagent_ids, retired_subagent_max_step, pending_sync }` where `pending_sync` is `None` or `{"synced_through": int}`. For zero-purge live upgrades from `v1.1.x` / `v1.2.x`, `validate_state` tolerates and strips legacy keys (`bound_tier`, `checkpoint_step`, `last_synced_step`, `prefix_digest`, `lmw_bytes` on top-level state; `tier`, `checkpoint_step`, `prefix_digest`, `lmw_bytes` in `pending_sync`) on read while rejecting unknown extra keys with exit `1` and always writing only the clean 4-key schema. `bind` requires non-null `pending_sync`, retires any different prior non-null `bound_subagent_id` at `max(retired_subagent_max_step.get(prev_id, -1), pending_sync.synced_through)` (emitting `"retired_subagent_id": prev_id` so `Trunk Session` can batch-kill it on the next tool turn), appends `<id>` to `execution_subagent_ids`, pops `<id>` from `retired_subagent_max_step`, and clears `pending_sync`. Default `reset` retires any active non-null `bound_subagent_id` at `max(retired_subagent_max_step.get(prev_id, -1), pending_sync.synced_through if pending_sync is not None else -1)` (using `-1` when `pending_sync` is `None` so mid-flight cancel races stay quarantined even across UI rewinds while preserving prior retired children's reports), then clears `bound_subagent_id` and `pending_sync` while preserving `execution_subagent_ids` and `retired_subagent_max_step`; `reset --purge` removes `state.json` unconditionally (used strictly on corrupt/invalid `state.json` exit `1`).

## Consequences

- Every `Execution Subagent` dispatch receives a fresh, lossless active-epoch `Living Memory Window` snapshot (`N_max = 1`), preserving full `<plan>` retention across child compaction and eliminating `RESUME_EXISTING` delta tracking, `prefix_digest` hashing, child-log byte scanning, `--force-spawn`, and `--tier` CLI flags.
- Spoofed `[Message]` payloads and late `<report>`s arriving after dispatch rotation or mid-flight cancel `reset` (even after UI rewind) cannot contaminate `Living Memory Window`.
- Existing `v1.1.x`/`v1.2.x` live sessions upgrade seamlessly to `v2.0.0` without triggering `reset --purge`, and `skills/orchestrator/scripts/sync_memory.py` stays pure Python 3 stdlib with deterministic replay coverage in `tests/test_sync_memory.py`.
