# Checkpoint-Bounded Living Memory Inheritance and Compaction-Synced Rotation

To give an Antigravity `Execution Subagent` the same living context as Official Orchestrator's shared-thread execution model without unbounded transcript growth or lossy manual summaries, a zero-dependency Python 3 standard-library CLI (`skills/orchestrator/scripts/sync_memory.py`, invoked via `py -3` on Windows or `python3` on POSIX relative to `SKILL.md`) resolves paths directly from `<Artifact Directory Path>` (`<appDataDir>/brain/<ConversationID>`)—reading `--transcript <Artifact Directory Path>/.system_generated/logs/transcript.jsonl` and writing session state into `--state-dir <Artifact Directory Path>/scratch/orchestrator`. CLI argument parsing overrides `ArgumentParser.error` to exit `1` (`0` = success, `1` = invalid arguments/state or `bind` when `pending_sync` is `null`, `2` = missing conversation parent directory, unreadable log, or corrupt mid-file JSONL); if `--transcript` does not yet exist or is 0 bytes on Turn 1 while its parent directory exists, `sync` emits a clean initial `SPAWN_NEW` (`checkpoint_step: -1`, `synced_through: -1`, `pages: []`, exit `0`). `sync` folds append-only records by canonical integer `step_index` (a later record at `k` invalidates earlier records at `>= k`, skipping trailing incomplete EOF lines) and enforces a hard session-origin backstop: if folded `step 0` has `type == "SYSTEM_MESSAGE"`, it exits `0` emitting `{"action": "SKIP_SUBAGENT_SESSION", ...}` without mutating `state.json`. Before filtering content, retained steps whose `"truncated_fields"` includes `"content"` are expanded from fixed sibling `transcript_full.jsonl` (matching 0-based line index first, then last matching `(step_index, type)`, or gracefully keeping compact `content` if `transcript_full.jsonl` is absent). Within `[max(0, latest_checkpoint_step) .. max_folded_step]` (using `-1` as the no-checkpoint sentinel), `sync` extracts `CHECKPOINT` `content`, `USER_INPUT` stripped of `<ADDITIONAL_METADATA>...</ADDITIONAL_METADATA>` and `<USER_SETTINGS_CHANGE>...</USER_SETTINGS_CHANGE>` and unwrapped at the outermost `<USER_REQUEST>...</USER_REQUEST>` (falling back to stripped text if tags are absent), non-empty `PLANNER_RESPONSE` string `content` (excluding `thinking`, `tool_calls`, `GENERIC`, and error notices), and `<report>...</report>` blocks inside `SYSTEM_MESSAGE`/`EPHEMERAL_MESSAGE` **only** when `[Message] ... sender=<id>` matches `<id> in state.execution_subagent_ids`. On every `sync`, stale `<state-dir>/pages/page_NNN.md` files are cleared before rendering sequential Markdown pages whose complete rendered size including page headers and separators satisfies `len(rendered.encode("utf-8")) < 40000` (splitting on message, line, and valid UTF-8 code-point boundaries). `<state-dir>/state.json` persists `{ bound_subagent_id, bound_tier, execution_subagent_ids, checkpoint_step, last_synced_step, prefix_digest, pending_sync }`, computing `prefix_digest` as `sha256` hex over canonical JSON `(step_index, type, extracted_text)` tuples across `[0 .. last_synced_step]`. Both `SPAWN_NEW` and `RESUME_EXISTING` use **symmetric two-phase commit**: `sync` stages `pending_sync` without advancing active watermarks, emitting `SPAWN_NEW` (`subagent_id: null`) whenever `bound_subagent_id` is `null`, `latest_checkpoint_step != checkpoint_step`, `max_folded_step < last_synced_step`, folded `prefix_digest` up to `last_synced_step` mismatches, `bound_subagent_id` is absent from folded `GENERIC`/`SYSTEM_MESSAGE` records (catching post-flush active-turn rewinds), or `tier != bound_tier`, and otherwise emitting `RESUME_EXISTING` (`subagent_id: bound_subagent_id`) over `(last_synced_step .. max_folded_step]`; `bind --state-dir <dir> --subagent-id <id>` commits `pending_sync` only after `invoke_subagent` or `send_message` succeeds and appends `<id>` to `execution_subagent_ids` (clearing the list on new `CHECKPOINT` epochs or rewinds), while `reset --state-dir <dir>` idempotently clears `state.json` and `pages/` for dead-subagent recovery. Empirical `L0-1` measurements (`44.1 KB` initial median, `4.3 KB` incremental median, `0%` `>45 KB` increments vs `211–818 KB` raw-tool bloat) confirm full intent preservation with compaction-synced rotation.
