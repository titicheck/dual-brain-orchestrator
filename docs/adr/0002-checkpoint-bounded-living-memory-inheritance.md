# Checkpoint-Bounded Living Memory Inheritance and Compaction-Synced Rotation

To give a cross-session native subagent the same living context as Official Orchestrator's shared-thread execution model without unbounded transcript growth or lossy manual summaries, a local zero-LLM helper will fold the Trunk's `transcript.jsonl` by canonical `step_index` and export the active `CHECKPOINT`-bounded **Living Memory Window** (`[latest CHECKPOINT (or Step 0) .. current_step]`), retaining 100% of `CHECKPOINT` compaction summaries, verbatim `USER_INPUT` requests (stripped of host metadata wrappers), visible `MODEL` replies, and prior subagent `<report>` messages while omitting raw exploration tool outputs (`GENERIC`) and private `thinking`. On first spawn, the subagent reads this snapshot (split into `<40 KB` pages if needed so each page fits one `46,080`-byte `read_file` call) alongside `<plan>`; on subsequent `send_message` continuations within the same compaction epoch, only the incremental slice `(last_synced_step, current_step]` is exported (or skipped if empty); whenever a new `CHECKPOINT` appears in the Trunk (`checkpoint_step > subagent_epoch_checkpoint`), the old subagent is left idle and a fresh native subagent is spawned inheriting `[new CHECKPOINT .. current_step]`. Empirical measurements across 66 `L0-1` handoffs showed full raw-tool mirroring bloats initial snapshots to `211–818 KB` (forcing 5–18 paginated reads and carrying stale file snippets that risk `edit_file` target mismatches) while `<=2 KB` hybrid thresholds add magic-number complexity and increase `>45 KB` overflows (`73%` vs `44%`); pure dialogue/checkpoint/report inheritance preserves all intent and decisions at `44.1 KB` initial median and `4.3 KB` incremental median (`0%` `>45 KB` on increments) while automatically coupling subagent retirement to the Trunk's own compaction lifecycle.
