# Dual-Mode Plugin Rule Activation, Global Flash Lock, and Unified Package Layout

To make the plugin toggle act as a drift-free global orchestration switch on Antigravity while preserving explicit on-demand control across standalone skill installations, we ship under the unified collision-free identifier `orchestrator` with exact repository layout: root manifests `plugin.json` (`{"name": "orchestrator", "displayName": "Orchestrator", "version": "1.0.0", "description": "..."}`), `.claude-plugin/plugin.json` (`{"name": "orchestrator", "version": "1.0.0", "description": "..."}`), and `.codex-plugin/plugin.json` (`{"name": "orchestrator", "version": "1.0.0", "description": "...", "skills": "./skills"}`), global rule `rules/AGENTS.md`, user guide `README.md`, self-contained skill module `skills/orchestrator/{SKILL.md, scripts/sync_memory.py, references/execution-protocol.md, references/harnesses.md}`, and Python `unittest` suites `tests/{test_sync_memory.py, test_package_contracts.py, fixtures/}`—with zero `hooks.json` startup scripts or background sidecars. On Antigravity, enabling the plugin automatically merges `rules/AGENTS.md` to activate global orchestration with the bound `Execution Subagent` strictly locked to `Model: "flash"` (prohibiting conversational tier drift, while disabling drops overhead to zero tokens per `agy-customizations/docs/plugins.md`); on Claude Code and Codex (whose plugin manifests do not auto-inject `rules/AGENTS.md` globally without hooks), plugin and skill installations expose `/orchestrator` on demand unless the user links the rule into their own `CLAUDE.md`/`AGENTS.md`. Manual `/orchestrator` invocations across all harnesses default to the fast execution tier (`"flash"` on Antigravity, `"sonnet"` on Claude Code, allowlisted fast model + `reasoning_effort: "medium"` on Codex) and permit explicit per-invocation tier overrides (`"pro"`, `"flash_lite"`, `"inherit"`, or harness equivalents).
