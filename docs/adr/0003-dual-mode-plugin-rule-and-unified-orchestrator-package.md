# Dual-Mode Plugin Rule Activation and Unified Orchestrator Package Layout

To make the plugin toggle act as a global orchestration switch on Antigravity while preserving explicit on-demand invocation across standalone skill installations, we will ship both a thin always-on routing rule (`rules/AGENTS.md`) and a self-contained skill (`skills/orchestrator/SKILL.md`) under the unified identifier `orchestrator` (verified collision-free across built-in and user `~/.gemini` customizations). When installed as a plugin (`plugin.json` at repository root alongside `.claude-plugin/plugin.json` and `.codex-plugin/plugin.json`), enabling `orchestrator` loads `rules/AGENTS.md` automatically while disabling it reduces context overhead to zero tokens (`agy-customizations/docs/plugins.md`); when installed as a standalone skill directory (`skills/orchestrator/`), behavior remains strictly opt-in via `/orchestrator`. All runtime assets (`SKILL.md`, `scripts/sync_memory.py`, `references/execution-protocol.md`, and `references/harnesses.md`) live inside `skills/orchestrator/` so plugin manifests, `rules/AGENTS.md`, and `README.md` remain thin wrappers with zero `hooks.json` startup shell scripts or background sidecar processes.
