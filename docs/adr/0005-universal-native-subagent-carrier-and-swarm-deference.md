# Universal Point-to-Point Native Subagent Carrier and Swarm Deference

To preserve high-altitude modularity, execution speed, and third-party skill compatibility under Occam's Razor while keeping V1 runtime optimization focused on Antigravity, we implement Antigravity's direct point-to-point primitive (`invoke_subagent` + `send_message`) in V1, keep the point-to-point Harness Adapter Seam cleanly isolated in `skills/orchestrator/references/harnesses.md` (with only concise harness-neutral extension notes and zero unverified third-party tool signatures), and rule out maintaining a parallel `swarm`-based execution carrier. Empirical Probe C (`02-exploratory-notes-and-host-probes.md` §3) showed that `swarm` with `fork: "coordinator"` silently ignored `model: "gemini-4-hydrogen-high"` in SQLite `gen_metadata` (executing on parent `M667` Carbon across `296,734` uncached raw-tool tokens), clean `swarm` workers strip `invoke_subagent` (blocking nested `egm-*` and `code-review` execution), board round-trips double continuation latency (`~26 s` vs `~12 s`) with one-turn-late tool registration, and Antigravity's live quota table confirms `claude-sonnet-5-5` shares the exact same quota pool as `claude-opus-5-5` while `invoke_subagent` (`"flash"` / `"pro"`) already offloads directly to the separate `Gemini 4 Hydrogen` (512k) pool. Native `/swarm` remains completely unencumbered for multi-agent board workflows: when a user explicitly invokes `/swarm`, `orchestrator` yields silently without interposing an `Execution Subagent`, and shared/workspace `AGENTS.md` auto-adoption stays inert inside board-woken `@<worker>` sessions just as it does inside `[Message] sender=<parent_uuid>` subagents.
