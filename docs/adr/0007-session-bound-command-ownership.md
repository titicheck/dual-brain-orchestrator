# Session-Bound Command Ownership Across the Dual-Session Split

Status: accepted & implemented (2026-11-20); implemented in [Ticket 08](../../.scratch/orchestrator-v1/issues/08-heavy-and-background-execution-delegation-gate.md).

## Context

The Occam adaptation ([02-occam-adaptation-to-native-subagents.md](../../.scratch/orchestrator-design/issues/02-occam-adaptation-to-native-subagents.md)) over Official Orchestrator ([01-official-orchestrator-system.md](../research/01-official-orchestrator-system.md)) identified three physical differences between Official Orchestrator's same-thread hot-swap and native-subagent dual sessions (using the canonical roles in [GLOSSARY.md](../../GLOSSARY.md), where `Trunk Session` is the planning session and `Execution Subagent` is the execution session): outbound `Living Memory Window` sync per [ADR-0002](0002-checkpoint-bounded-living-memory-inheritance.md), native delegation, and inbound `<report>` return per [ADR-0001](0001-unified-subagent-report-return-into-plan-review.md).

Production session `L0-3` exposed a fourth physical difference: a host background process belongs to the session that started it, and host completion or status wakeups are delivered only to that session. In single-thread Official Orchestrator this ownership is invisible; across two sessions, when `Trunk Session` leaves a long read-only command running on turn exit (observed in `L0-3` Route 1 `[plan review]` turns at `Trunk Session` steps `268`, `318`, `347..351`, and `378`), host completion or failure wakeups (`~56m`, `~63m`, `~78m`) repeatedly wake the high-context `Trunk Session` across the `300`-second prompt-cache time-to-live (TTL) cliff (`~$11.18` wasted; evidence in [05-production-telemetry-ttl-and-lifecycle-audit.md](../research/05-production-telemetry-ttl-and-lifecycle-audit.md)). Symmetrically, by deduction from the every-exit `<report>` return contract ([ADR-0001](0001-unified-subagent-report-return-into-plan-review.md)), an `Execution Subagent` that sends `<report>` while a command it started is still running wakes `Trunk Session` with an output-less report and is later re-woken by the host when the command finishes, emitting a second `<report>`.

## Decision

Adopt one symmetric invariant: **no session yields control (`Trunk Session` ending its turn, `Execution Subagent` sending `<report>`) while a command it started is still running.**

1. **`Trunk Session` side (pure invariant — Official Parts 2.1, 2.4, and 7 capabilities preserved):** Declare the command-ownership invariant globally at top-level `SKILL.md` scope (covering all `Trunk Session` turns: Step 6, Planning Turn, and `[plan review]`), keeping Official Part 2.1 (`Direct Answer Gate`), Part 2.4 (read-only observational commands), and Part 7 (`[plan review]` observational checks) intact in core protocol rules, subject only to the invariant: any observational command `Trunk Session` starts must complete before `Trunk Session` yields (terminate any started command that unexpectedly does not finish before yielding, and delegate instead). Host-specific consequences—on Antigravity, `run_command` synchronous wait is capped at `WaitMsBeforeAsync <= 10000 ms`, longer commands auto-background and notify only the invoking session, and turn-internal polling is discouraged, so commands `Trunk Session` can complete in-turn are effectively those finishing within the synchronous window while longer builds, test suites, benchmarks, and probe scripts go into `<plan>`—live strictly in [harnesses.md](../../skills/orchestrator/references/harnesses.md).
2. **`[plan review]` three-tier verification ladder (eliminating redundant re-runs while preserving strict Three-Way Exit):**
   - *Tier 1 (clean `<report>`):* lightweight footprint check only (`git status --short` / `git diff --stat`), zero re-runs of passing tests or benchmarks.
   - *Tier 2 (incomplete, ambiguous, or inconsistent `<report>`):* inspect the bound child's host-recorded `transcript.jsonl` per [harnesses.md](../../skills/orchestrator/references/harnesses.md) plus targeted file reads first (zero re-runs if host logs confirm execution and pass).
   - *Tier 3 (confirmed missing, wrong, or untrusted verification):* run an observational check in `Trunk Session` only if it finishes before yielding, or dispatch missing or additional long verification to `Execution Subagent` via standard `[plan review]` Exit 1/2 (using existing [harnesses.md](../../skills/orchestrator/references/harnesses.md#4-recovery--model-quota-errors-on-antigravity) `reset` + respawn recovery if the bound child is unresponsive or unrevivable).
3. **`Execution Subagent` side:** Awaiting an in-flight command's completion is **not** an exit to the parent. `Execution Subagent` sends `<report>` only after every command it started reaches a terminal state; on any early hand-back trigger, it stops plan work immediately, terminates any still-running or persistent command it started, and then delivers `<report>`. A still-running command is never a safe boundary for the `~30`-turn interim report.
4. **Honest Role-Split Statement:** The Official Orchestrator judgment/execution split stays intact (`Trunk Session` retains planning, decisions, choosing verification commands and expected outputs, reviewing host-recorded outputs, and `[plan review]` exits; `Execution Subagent` retains execution). Under Antigravity's `10s` synchronous cap, the practical consequence of the host invariant is explicitly acknowledged: `> 10s` observational builds and tests move off `Trunk Session` into `<plan>`, and persistent services cannot outlive a dispatch on either side (noted in `<plan>` authoring when relevant).

## Consequences

- Eliminates `Trunk Session` background wakeups (`~$11.18` on `L0-3`), prevents redundant test re-runs on clean or host-log-verifiable `<report>`s, and prevents child double-report wakeups.
- Leaves Official Part 2.1 (`Direct Answer Gate`), `README.md` and `README.zh-CN.md` adoption snippets, [ADR-0004](0004-coexistence-boundaries-and-foreman-subagent-delegation.md), `sync_memory.py`, and `~30`-turn counting mechanics untouched, with zero hooks or sidecars ([ADR-0006](0006-pareto-boundary-reject-lifecycle-hooks-and-workflow-carrier.md)).
- Persistent services cannot outlive a dispatch on either side; a misjudged `Trunk Session` command costs at most one synchronous wait window before termination.
